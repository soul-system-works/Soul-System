AMENDMENT ID:    SOUL-A031
DATE:            2026-11-05
WITNESS IDS:     None — the source is SOUL-I085, the Body's own words: "i have to
                 "ratify" something all the time. i hate it. i think the witness
                 docs (i think that is what it is for) should be autoratified with
                 opt out. this way it isn't an extra commit or extra step all the
                 time in the workflow".
WHAT CHANGES:    A model-initiated idea or witness capture is appended at once,
                 unmarked, and counts as accepted — whether or not the Body is
                 there. The reply that appended it says so in one line ("Added
                 THERMAL-231 to witness.md — say no to strike it"); no draft, no
                 question. On a no, the entry stays and is marked declined, as the
                 old no-path did; silence keeps it. The mark
                 `unconfirmed — owner to ratify` and the ratify step are retired.
                 /soul-handoff no longer marks or scans; its cursor's `UNCONFIRMED`
                 field becomes `NEW ENTRIES` — the id of every entry the model
                 added this session, written fresh each cursor and never carried.
                 /soul-resume names them in one line instead of asking; an old
                 cursor's `UNCONFIRMED` ids are treated as accepted and named the
                 same way. The stores are not scanned; a leftover mark is ignored.
                 Unchanged: finding mode (the Body's explicit act), the F044
                 triage rule, rule 2, and captures the Body starts — a witness
                 entry the Body types still shows its draft for go / edit /
                 cancel (until v3.9.1, below), and a Body's idea is still jotted
                 at once.
WHERE IN SOUL:   skills/soul-capture, skills/soul-handoff, skills/soul-resume,
                 skills/soul-help;
                 docs/using-the-soul.md; operations/codex.md;
                 tools/test_capture_opt_out.py (replaces
                 tools/test_unconfirmed_mark.py).
QUESTION ONE:    Evidence — the Body's statement (SOUL-I085); asked the scope,
                 the Body chose the option 'Opt-out everywhere'. The ratify
                 step came from A028's ruling of F065 (2026-10-19), which made
                 unattended captures append marked instead of being held.
QUESTION TWO:    Necessity — the Body had to confirm each entry the model
                 started (a go before it was appended, or a ratify after one
                 appended while the Body was away), and the record took a commit
                 for each ratify. The Body does this all the time and named it as
                 the cost.
QUESTION THREE:  Coherence — the veto survives as an opt-out: every entry the
                 model adds is named in chat in one line — in the reply that adds
                 it, and again through the cursor's NEW ENTRIES at handoff and
                 resume — and a no still marks it declined. Append-only is untouched. Finding mode is
                 untouched: graduation still waits for the Body. What would make
                 this wrong: a model-invented or wrong entry the Body never
                 notices, so it stands in the record as accepted — mitigated by
                 the one-line mention, and by rule 2 (never invent history), which
                 still governs what is written. No incident of this is known; none
                 is claimed.
STATUS:          Accepted 2026-11-05 by the Body, who chose the option
